# Exhibit Stage 1: Core and CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust library (`exhibit-core`) that scans folders, identifies movies and shows, stores everything in SQLite, launches mpv with resume tracking, and exposes every operation through a JSON-speaking `exhibit` command-line tool.

**Architecture:** A Cargo workspace with two crates. `exhibit-core` holds all behaviour behind one `Library` facade; that facade is the tool surface later reused by the Tauri UI and the MCP server. `exhibit-cli` is a thin `clap` wrapper that prints JSON. The core is synchronous and never calls an AI model.

**Tech Stack:** Rust stable (MSVC toolchain), `rusqlite` (bundled SQLite with FTS5), `serde`/`serde_json`, `thiserror`, `walkdir`, `regex`, `strsim`, `ureq`, `keyring`, `windows-sys`, `clap`, `tempfile` (tests). Add each with `cargo add` at its latest stable version.

**Spec:** `docs/superpowers/specs/2026-11-14-exhibit-design.md` (sections 8 to 13, 16). Stages 2 to 5 get their own plans after this one ships.

**Deferred to the stage 2 plan:** watching sources for changes while the window is open, and deciding when thumbnails for Other are generated (the `thumbnail` function is built here; the UI triggers it).

## Global Constraints

- Windows 11 first. Do not use APIs that block a later Linux port without putting them behind `#[cfg(windows)]` with a stub for other platforms.
- Exhibit never renames, moves, deletes or writes inside a media folder. It only reads there.
- No media tool is bundled. mpv, ffprobe and ffmpeg are found on the machine or set by the owner.
- The core never calls an AI model.
- Secrets (TMDB key, agent key) live in the OS credential store, never in the database or a plain file.
- SQLite runs in WAL mode; several processes may open the database at once.
- Data directory: `%APPDATA%\exhibit` (database `exhibit.db`, image cache `cache\images`). The environment variable `EXHIBIT_DATA_DIR` overrides it; every test uses a temporary directory.
- All timestamps are Unix seconds (`i64`). All durations and positions are seconds (`f64`).
- Watched threshold: position / duration >= 0.90.
- Tests never touch the network, the real credential store, or real media tools.
- Every commit message ends with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- Suggested model per task: Opus for tasks 2, 4, 8 and 10; Sonnet for the rest.

## Review Focus

1. **Drive unplugged during or between scans.** A source whose root is unreachable must leave every file and item untouched and report the source as offline, never as "all files removed". Pinned in Task 4.
2. **Titles that are numbers or contain a year.** `1917`, `2012`, `2001: A Space Odyssey`, `Blade Runner 2049` must not have their title eaten as a year. Pinned in Task 2.
3. **Non-ASCII and awkward paths.** Accented, CJK and emoji file names, and paths longer than 260 characters, must scan, store and round-trip unchanged. Pinned in Tasks 2 and 4.
4. **Network or TMDB failure in the middle of identification.** Items already matched stay matched, the failing item stays unmatched and is retried on the next run, and the run reports the error instead of aborting silently. Pinned in Task 8.
5. **A file the probe tool cannot read** (truncated, zero bytes, wrong extension). The file still appears in the library without technical details, and probing continues with the next file. Pinned in Task 6.

Rules the tests pin down: the file name is parsed first; when it yields no usable title (only an episode number, or under 2 letters), the parent folders supply the title and season (`Season 2`, `S02`, `Specials` = season 0). A bare leading number in a group-tagged name (`[Group] Title - 05`) is an absolute episode with `season: None`.

```rust
pub const VIDEO_EXTENSIONS: &[&str] = &["mkv","mp4","m4v","avi","mov","wmv","ts","m2ts","webm","mpg","mpeg","flv"];
pub struct ScanReport { pub source_id: Id, pub online: bool, pub added: u32, pub changed: u32,
    pub moved: u32, pub removed: u32, pub unchanged: u32 }
pub enum ScanEvent { Started { source_id: Id }, FileAdded { file_id: Id, rel_path: String }, Finished(ScanReport) }
pub fn add_source(c: &Connection, v: &dyn Volumes, path: &Path) -> Result<Source>;
pub fn remove_source(c: &Connection, id: Id) -> Result<()>;      // deletes its files; items left without files stay, hidden

pub fn scan_source(c: &Connection, v: &dyn Volumes, id: Id, on: &mut dyn FnMut(ScanEvent)) -> Result<ScanReport>;
```

Behaviour: a source stores its volume id and its path relative to the volume root, so a changed drive letter resolves. If the root cannot be listed, return a report with `online: false` and change nothing. New file: insert `files` row and one `items` row (`kind: Other`, `match_state: Unmatched`, `title` = `parse_path(..).title`), linked. Changed (same path, different size or mtime): update and set `probed = 0`. Moved (a missing row and a new path share size, mtime and file name): update `rel_path`, keep `item_id`. Removed: delete the `files` row only; the item row stays so history and manual matches survive. Skip files matching `(?i)\bsample\b` under 150 MB. An unreadable subfolder is skipped, not fatal. Adding a source that is inside or contains an existing source returns `Error::Invalid`.

### Task 6: Technical details (probe)

**Files:**
- Create: `crates/exhibit-core/src/probe.rs`, `crates/exhibit-core/tests/fixtures/ffprobe/{sdr_1080p.json,hdr10_2160p.json,dolby_vision.json,hlg.json}`
- Test: inline

**Interfaces:**
- Consumes: `tools::Tools`, `TechInfo`.
- Produces:

```rust
pub fn parse_ffprobe(json: &str) -> Result<TechInfo>;
pub fn parse_mpv_properties(track_list: &serde_json::Value, video_params: &serde_json::Value, duration: f64) -> Result<TechInfo>;

```

ffprobe command: `ffprobe -v error -print_format json -show_format -show_streams <file>`. HDR mapping: any video stream side data mentioning `DOVI` gives `"Dolby Vision"`; else `color_transfer == "smpte2084"` gives `"HDR10"`; `"arib-std-b67"` gives `"HLG"`; otherwise `None`. mpv fallback: start `mpv --no-config --pause --vo=null --ao=null --input-ipc-server=<pipe> <file>`, read `duration`, `track-list`, `video-params` over the JSON control channel, then quit; `video-params.gamma` `pq` gives `"HDR10"`, `hlg` gives `"HLG"`. `probe_pending` handles files with `probed = 0` on online sources; each file is marked `probed = 1` whether it succeeds or fails, and a failure never stops the loop. Thumbnails: `ffmpeg -ss <t> -i <file> -frames:v 1 -vf scale=640:-2 <dest>` or `mpv --no-config --start=<t> --frames=1 --vo=image --vo-image-outdir=<dir> ...`.

Pipeline per unmatched file-backed item: (1) an `.nfo` with an ID resolves through `find_external` or directly and is applied with `MatchSource::Nfo`, no scoring; an `.nfo` without an ID overrides the parsed title and year. Artwork: on match, download poster at `w780` and backdrop at `original` into `cache_dir/<tmdb_kind>-<id>-poster.jpg` and `-backdrop.jpg`, store the file names; a failed download leaves the field null and does not fail the match.
